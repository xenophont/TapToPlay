# Adyen Setup

This document describes how TapToPlay talks to the Adyen Android Payments app and the Adyen Management/Payments App APIs.

## Payments App Links

TapToPlay uses the documented Android Payments app links:

- Test boarded check: `https://www.adyen.com/test/boarded`
- Test board: `https://www.adyen.com/test/board`
- Test payment: `https://www.adyen.com/test/nexo`
- Live boarded check: `https://www.adyen.com/boarded`
- Live board: `https://www.adyen.com/board`
- Live payment: `https://www.adyen.com/nexo`

The return URL is:

```text
taptoplay://adyen-return
```

Payment launches use the documented `request` query parameter. The value is a Base64URL-encoded encrypted Nexo envelope generated by `NexoCrypto`.

## Profile Selection

Credentials can come from either:

- `local.properties`, for debug-only local developer bootstrap.
- A scanned QR profile, stored in encrypted Android preferences.

Switching test/live is deliberate. Select the active profile in `Payments App`; test profiles use test App Links and Management API hosts, and live profiles use live App Links and Management API hosts.

Release builds do not embed `local.properties` Adyen values. Use QR profiles for portable demos, and never commit real credentials.

## Boarding Flow

1. Open `Payments App`.
2. Select the target profile.
3. Tap `Check`.
4. TapToPlay opens `boarded?returnUrl=taptoplay://adyen-return`.
5. If the Payments app is not boarded, Adyen returns `installationId` and `boardingRequestToken`.
6. Tap `Board`.
7. TapToPlay calls `generatePaymentsAppBoardingToken` with the returned `boardingRequestToken`.
8. TapToPlay opens the `board` App Link with the Base64URL-encoded `boardingToken`.
9. The Adyen app returns `boarded=true` and an `installationId`.

Use `Reboard` to open `boarded?reboard=true`, receive a fresh `boardingRequestToken`, and then tap `Board` to finish setup for the selected merchant/store context.

TapToPlay decodes the returned `data` payload when present and shows readable boarding/reboarding context in the result dialog and diagnostics.

## Payments App Instance Operations

The `Payments App` tab includes guarded operations using the selected profile API key:

- `Refresh`: lists Payments App instances for the selected merchant, or for the selected store when `storeId` is present.
- `Revoke instance`: revokes a listed installation after an explicit confirmation.
- `Remove`: removes only the local encrypted profile and saved local boarding state.

`Remove` and `Revoke instance` are intentionally separate:

- Use `Remove` when the local demo profile should disappear from this device.
- Use `Revoke instance` when the Adyen Payments app installation should be invalidated in Adyen and must be boarded again.

The API credential must have the required roles for boarding-token generation, listing Payments App instances, and revoking instances.

## Payment Flow

1. Add products in `Catalog`.
2. Open `Checkout`.
3. Optionally scan or select a SaleToAcquirerData favorite.
4. Tap `Charge test payment`, or `Charge live payment`.
5. Live payments show a confirmation dialog with amount, item count, profile, environment, merchant, and store.
6. TapToPlay builds a structured Terminal API request in the `adyen` package.
7. `NexoCrypto` encrypts the Terminal API payload and creates the App Link `request` value.
8. The Adyen Payments app returns a Terminal API response payload to `taptoplay://adyen-return`.
9. TapToPlay records approved/refused/failed status only from a full Terminal API response.

Short return values such as `result=success` are treated as diagnostic failures, not as approved payments. This prevents generic or spoofed return URLs from marking transactions as paid.

## Refund Flow

Approved payment records with a Terminal API transaction identifier enable `Refund` in the transaction inspector. TapToPlay builds a referenced `ReversalRequest`, encrypts it, and opens the Adyen Payments app with the same `request` App Link pattern.

Refund outcome handling depends on the Terminal API response returned by the Payments app. Adyen webhooks or Customer Area checks may still be needed for operational reconciliation.

## Live Checklist

- Use a live QR profile with `environment: "live"`.
- Verify the active profile in `Payments App` before checkout.
- Confirm the live Adyen Payments app is installed and boarded.
- Refresh Payments App instances if you need to verify the installation state.
- Confirm each live charge in the checkout confirmation dialog.
- Do not ship this in-app credential model to production users.

## Troubleshooting

- QR scan fails: validate the payload against `docs/QR_CREDENTIALS.md`, including payload size and required fields.
- Boarding fails: check the API key, merchant account, store ID, environment, and Adyen API roles.
- Payments App API refresh/revoke fails: check the selected profile API key permissions and whether the merchant/store scope is correct.
- Adyen app does not open: confirm the Payments Test app is installed for test flows, or the live Payments app for live flows.
- Return dialog does not appear: confirm the return URL is `taptoplay://adyen-return`.
- Payment returns a short result only: inspect the transaction failure; TapToPlay requires a full Terminal API response payload to mark approved/refused.
- Nexo crypto errors: verify the terminal key identifier, key version, terminal passphrase, environment, and POIID/installation ID.

## Español

TapToPlay usa App Links de Adyen Payments para `boarded`, `board` y `nexo`. La return URL es `taptoplay://adyen-return`, y los pagos usan el parámetro `request` con un sobre Nexo cifrado y codificado en Base64URL.

Flujo de boarding:

1. En `Payments App`, selecciona el perfil.
2. Toca `Check`.
3. Si Adyen devuelve `boardingRequestToken`, toca `Board`.
4. TapToPlay llama a `generatePaymentsAppBoardingToken`.
5. La app abre el link `board` y recibe `boarded=true` con `installationId`.

La pestaña `Payments App` también permite listar instancias y revocar una instalación con confirmación explícita. `Remove` solo borra el perfil local cifrado; no revoca la instalación en Adyen.

Los pagos live requieren confirmación por cada cargo. TapToPlay solo marca transacciones como aprobadas o rechazadas cuando vuelve una respuesta completa de Terminal API.
